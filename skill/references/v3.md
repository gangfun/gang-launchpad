# Tax tokens with a recipient (LaunchpadV3)

A V3 token is a normal bonding-curve token (Agent-only curve, 1% wallet cap, graduates at ≈15 BNB of its quote into a
PancakeSwap V2 pool) with **its own buy and sell tax**, set once at create and charged both on the curve and in the pool:

- `--buy-tax` / `--sell-tax`: 1–5% each, set separately (e.g. 2% / 2%).
- Of every tax, **the platform keeps 0.5% of the trade volume** (so a 2% tax: 0.5% platform, 1.5% shared out).
- `--dividend`: 0–100% of what is left goes to holders (holding ≥10,000 tokens, by balance); the rest goes to
  `--recipient` **in the quote token** (BNB → WBNB, USDT, …), never in the token itself.
- `--recipient` must be on the platform's whitelist (e.g. a partner's treasury contract). It can't be changed later.
  Only `--dividend 100` may leave it out.
- The curve's own 1% fee is charged on top of the tax on every curve trade.

Payments: on the curve the recipient is paid in the same tx as the trade. In the pool the tax is collected in the token
and the platform keeper sells it for the quote about once an hour, then pays. If a payment to the recipient fails
(e.g. the quote token blocks that address), it is **recorded as owed**, the trade still goes through, and anyone can push
it later with `gang v3 release`.

**For now V3 runs on BSC testnet only (until its audit): every `gang v3` command needs `--testnet`.** Without it the CLI
answers `LaunchpadV3 is not deployed on BSC mainnet yet`. Testnet tokens and quotes have no value; say so if the user asks.
`gang create` with `--buy-tax` / `--sell-tax` / `--dividend` / `--recipient` is refused and points here.

`--quote` must be on gang's quote whitelist (listed 18-decimal tokens with a fixed rate, such as USDT; anything else
fails with `QuoteNotAllowed`); leave it out for WBNB. The graduation amount uses gang's fixed rate, not a pool.

`create` also builds the token's **metadata JSON** — name, symbol, `--description`, the logo as `image`, `--website` as
`external_link`, `--twitter` — uploads it to gang.fun and fixes its URL on-chain as the token's `contractURI()` /
`metaURI()` (ERC-7572). It can't be changed later, so get the links right before executing. The output shows `metaURI`
and the `metadata` that was uploaded. `gang fair create` does the same.

```bash
gang v3 create --name "My Token" --symbol MYT --buy-tax 2 --sell-tax 2 [--dividend 0] --recipient 0x… [--quote 0x… --ref-pool 0x…] [--logo ./avatar.png | --logo-uri URL] [--website URL] [--twitter @handle] [--description "…"] --testnet
gang v3 buy --token <addr> --amount <quote> [--slippage 1] --testnet     # amount includes the 1% fee and the buy tax
gang v3 sell --token <addr> (--amount <tokens> | --all) [--slippage 1] --testnet
gang v3 info --token <addr> --testnet         # curve, tax setting, recipient (+ whitelist name), what is still owed to it
gang v3 release --token <addr> --testnet      # push an owed payment to the recipient (the caller gets nothing)
gang v3 income --recipient <addr>             # what a recipient received, per token (from gang.fun)
gang v3 list [--status curve|graduated|all]   # V3 tokens on gang.fun
gang execute --request-id …
gang v3 tx --hash 0x… --testnet               # decode Created / TaxConfigured / Buy / Sell / TaxPaid / TaxOwed / …
```

## Reading results

- `create` preview: `split` spells out who gets what of each tax (while no holder has 10,000+ tokens, the holders' part
  goes to the recipient); `recipientLabel` is the whitelist name. Read both to the
  user before they confirm: the rates and the recipient are permanent. `tax setting refused: recipient not listed` means
  the address is not on the whitelist; it can't be used.
- `buy`: `expectTokens` / `minTokensOut`; `spend` already includes fee and tax. At the wallet cap the excess is refunded.
- `sell`: `expectOut` is what arrives after the fee and the sell tax.
- **WBNB-quoted tokens**: `gang v3 buy` pays native BNB through GangRouter in one tx (`via: 'router'`; at the wallet cap
  the excess comes back as BNB). Sells always go to the pad directly. `--use-wbnb` pays from WBNB instead.
- Otherwise a write command may return a setup step first: `step: 'wrap-bnb'` (WBNB quote short), `step: 'approve-quote'` (buy) or
  `step: 'approve'` (sell: the token itself). Execute it,
  then **run the same command again** for the real step.
- `info.owedToRecipient` > 0: a payment failed earlier; `gang v3 release` sends it once the recipient accepts the quote.
- `--note` / `--follow` are refused on `gang v3` (the server cannot match them to a V3 tx yet). `--calldata` and
  `--from` work as in `gang fair` (raw tx instead of a baw preview, e.g. if the Agentic Wallet does not sign on testnet).
- Env: `GANG_V3_TESTNET_PAD` / `GANG_V3_TESTNET_RPC_URL` override the testnet deployment; `GANG_V3_PAD` is for mainnet;
  `GANG_ROUTER_TESTNET` / `GANG_ROUTER` the router.

Flow: preview → show the user the tax rates, the split and the recipient (create) or amounts (buy / sell) → confirm →
`gang execute` → `gang v3 tx --hash … --testnet`. Link the token: `https://gang.fun/token/<token>`.
