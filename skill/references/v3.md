# Tax tokens with a recipient (LaunchpadV3)

A V3 token is a normal bonding-curve token (Agent-only curve, 1% wallet cap, graduates at ≈15 BNB of its quote into a
PancakeSwap V2 pool) with **its own buy and sell tax**, set once at create and charged **only in the pool, after
graduation**. On the curve a V3 token trades like any other: **only the 1% fee, no tax** (nothing goes to the recipient or
to holders from curve trades).

- `--buy-tax` / `--sell-tax`: 1–5% each, set separately (e.g. 2% / 2%). Leave both out for an **untaxed** token.
- Of every pool tax, **the platform keeps 0.5% of the trade volume** (so a 2% tax: 0.5% platform, 1.5% shared out).
- `--dividend`: 0–100% of what is left goes to holders (holding ≥10,000 tokens, by balance); the rest goes to
  `--recipient` **in the quote token** (BNB → WBNB, USDT, …), never in the token itself.
- `--recipient` defaults to **your own address** (the creating wallet; no whitelist needed); or set it to a partner on the platform's
  whitelist (e.g. a partner's treasury contract). Any other address is refused. It can't be changed later.
  Only `--dividend 100` may leave it out.
- Curve trades pay only the 1% fee (to the platform), no tax. Dividend shares are still tracked on the curve (by
  balance), so curve buyers who still hold at graduation earn from the pool tax.

Payments: the tax is collected in the token, in the pool;
holders' dividend share of it is credited to whoever holds at that moment — never to the trader for its own trade's tax
(a seller does not get a dividend from its own sell tax). It is sold in small chunks: right before a
taxed sell into the pool (at most 25% of that sell), or by the platform keeper when no sells come. All chunks of a token
in one block share one budget: at most 0.5% of the pool's token side (as it stood at the block's first chunk) in total,
and no chunk sells while the price is more than 2% below where the block started. Each chunk's quote is paid out at
once. A sell therefore fills a little below a plain `getAmountsOut` quote (about half the sell's own price impact more);
the handler's `previewSellNextBlock(token, amount)` gives the amount with the chunk included as of the next block — the
one a sent tx lands in — and is what to use for a seller's `amountOutMin` (`previewSell` is this block's, and comes out
too high once this block's budget is spent). A sell that triggers a chunk uses about 660k gas (about 330k without); let the
wallet estimate it. If a payment to the recipient fails
(e.g. the quote token blocks that address), it is **recorded as owed**, the trade still goes through, and anyone can push
it later with `gang release`.

**Mainnet by default**: CLI 0.9.0 has the mainnet GangLaunchpad (`0x15CFD2dc8278Fb87a1783ef42111618E20874365`) and
GangRouter (`0xE040445690Aa56C8b68B7f7038C7b2562B5079C4`) built in, so V3 runs on BSC mainnet; `--testnet` uses
BSC testnet (set 10). `… has no mainnet address in this CLI version yet` means an older build: install 0.9.0
([SKILL.md](../SKILL.md)). Testnet tokens and quotes have no value; say so if the user asks.

**One pad for V3 and 打新**: V3 tokens and 打新 (fair-mint) sales live on the same GangLaunchpad (one address, one tax
handler, one GangRouter). `gang info|status|buy|sell|claim|release --token <addr>` read the pad's `kindOf` and run the V3
code for a V3 token (`kind: "v3"` in the result); `gang release` on a 打新 token fails with a `hint`. `gang v3 <sub>` is
an alias of the same code (CLI 0.12.0+, its results carry `useInstead`); given a 打新 token it fails with `this is a 打新
(fair-mint) token, not a V3 token: …`.
`gang create` makes a V3 token (`gang v3 create` is its alias; every new token launches here; LaunchpadV2 takes none).
**Untaxed:** leave out `--buy-tax` / `--sell-tax` (and `--dividend` / `--recipient`, which are refused without them): no
pool tax, no dividend, no recipient; the curve still charges the 1% fee. Taxed needs both, 1–5% each.

`--quote` is WBNB when left out, or any 18-decimal ERC-20 (e.g. a stock token; other decimals fail with `QuoteNotAllowed`).
As with `gang create`, a non-WBNB quote needs `--ref-pool`: a PancakeSwap V2 pair or V3 pool holding it, which prices the
≈15 BNB graduation target at create (V3 pools use a 30-minute TWAP; a pool against USDT is bridged to WBNB on mainnet).
Mainnet USDT needs no `--ref-pool`: it defaults to the Pancake V3 USDT/WBNB 0.01% pool. If gang has set a fixed rate
for a quote, the rate is used and `--ref-pool` is optional. The create
output shows `graduationAt` in the quote; pick the deepest pool.

`create` also builds the token's **metadata JSON** — name, symbol, `--description`, the logo as `image`, `--website` as
`external_link`, `--twitter` — uploads it to gang.fun and fixes its URL on-chain as the token's `contractURI()` /
`metaURI()` (ERC-7572). It can't be changed later, so get the links right before executing. The output shows `metaURI`
and the `metadata` that was uploaded. `gang create --fair` does the same.

```bash
gang create --name "My Token" --symbol MYT [--buy-tax 2 --sell-tax 2 [--dividend 0] [--recipient 0x…]] [--quote 0x… --ref-pool 0x…] [--logo ./avatar.png | --logo-uri URL] [--website URL] [--twitter @handle] [--description "…"] [--testnet]
gang buy --token <addr> --amount <quote> [--slippage 1] [--testnet]     # amount includes the 1% fee (no tax on the curve)
gang sell --token <addr> (--amount <tokens> | --all) [--slippage 1] [--testnet]
# graduated: the same two commands trade in the PancakeSwap pool through GangRouter (see "Pool trades" below)
gang buy --token <addr> --amount <n> [--slippage 1] [--use-quote | --pay-bnb] [--testnet]
gang sell --token <addr> (--amount <tokens> | --all) [--slippage 1] [--to-bnb] [--testnet]
gang info --token <addr> [--testnet]            # curve, tax setting (taxNote: pool only), recipient (+ whitelist name), what is still owed to it; graduated: swapBack
gang release --token <addr> [--testnet]         # push an owed payment to the recipient (the caller gets nothing)
gang status --token <addr> [--slippage 1] [--testnet]      # my balance; dividend: claimable now + credited to me, not sold yet (estimate); graduated: poolSellAll
gang claim --token <addr> [--testnet]           # claim my dividend (paid in the quote token)
gang v3 income --recipient <addr>             # what a recipient received, per token (from gang.fun)
gang list --kind v3 [--status curve|graduated|all]   # V3 tokens on gang.fun
gang execute --request-id …
gang tx --hash 0x… [--testnet]                  # decode Created / TaxConfigured / Buy / Sell / TaxPaid / TaxOwed / …
# aliases: gang v3 list|info|status|create|buy|sell|claim|release|tx (same flags)
```

## Pool trades (graduated token, PancakeSwap through GangRouter)

On a graduated token `gang buy` / `gang sell` no longer stop at a quote: they build the PancakeSwap trade through
GangRouter (the same proxy as the BNB curve buys). The same holds for a 打新 token after launch ([fair.md](fair.md)) and
for a graduated V2 / Soft / U / S token (mainnet, [trade.md](trade.md)). The tokens / the proceeds go straight to the wallet. The pool has no Agent gate and no wallet cap;
the token's pool tax applies.

- **Buy** (`--amount` = what you pay; `--bnb` is its older name):
  - WBNB-quoted: native BNB by default (`function: poolBuyBNB`, path WBNB → token); `--use-quote` pays from WBNB
    (`poolBuy`; wraps / approves first).
  - Other quote (e.g. a stock token): pays the quote (`poolBuy`, approve the quote first); `--pay-bnb` pays native BNB
    routed WBNB → quote → token (`poolBuyBNB`; needs a WBNB/quote pool on Pancake, else it fails with a hint).
  - `minTokensOut` = Pancake `getAmountsOut` on that path, less the token's **buy tax** (`buyTaxPct`), less `--slippage`
    (default 1%). `expectTokensBeforeTax` / `expectTokens` show both.
- **Sell** (`--amount <tokens>` or `--all`): `poolSell` pays the quote; `--to-bnb` → `poolSellForBNB` pays native BNB
  (path token → quote → WBNB when the quote is not WBNB).
  - `minOut` = the tax handler's `previewSellNextBlock` (sell tax and the chunk of held tax sold first included, as of
    the next block; `quotedWith`), less `--slippage`. With `--to-bnb` and a non-WBNB quote, that quote amount is then
    priced quote → WBNB with `getAmountsOut` (`expectQuoteBeforeBnb`). Where the handler has no quote (V2 tokens, an
    untaxed V3 token) `minOut` comes from `getAmountsOut` of the amount less the sell tax (`quotedWith: getAmountsOut`).
  - **Gas**: a taxed sell needs about **700k gas** (it also sells one chunk of the held tax first). Let the wallet
    estimate it, or give at least **750k**; too little reverts with `SwapBackOutOfGas`. The output says so in `gas`.
- **Approvals, only this trade's amount**: a sell first returns `step: 'approve'` (the token → the router), a quote buy
  `step: 'approve-quote'` (and `wrap-bnb` before it when WBNB is short). Execute it, then **run the same command again**
  for the trade itself (`next` / `then` show what follows, with its minimum). With `--calldata` every tx comes at once
  in `steps[]`, in order (`tx` is the first); the trade there is not simulated, since it needs the approve mined first.
- **The router is checked before any step** (an approve to the wrong address would hand it the tokens): it must be a
  contract, not the PancakeSwap router nor the tax handler's `dexRouter()`, answer `pad()` (= the CLI's pad) and `wbnb()`,
  and be the version with pool trades (`pancakeRouter()`, and the pool function itself answering a zero-amount call with
  `ZeroAmount`). Otherwise it fails with `… is not a GangRouter (…)` or `… is an older version without PancakeSwap trades`
  (e.g. the testnet set-8 router 0xaeC6…5747, which is not a proxy and can't be upgraded): no approve is offered. Quotes
  use that router's own `pancakeRouter()`, the Pancake router the trade swaps through.
- The trade is `eth_call`ed before the preview. A revert returns `success: false` with the reason and a `hint`:
  `TooLittleReceived` (`args: [received, minimum]`: the pool pays less than the minimum — re-run to re-quote, or raise
  `--slippage`), `Expired` (the 30-min `deadline` passed: re-run), or a Pancake / token reason. With `--calldata` it
  carries `doNotSend: true` and the tx only as `unsentTxForInspection` (no `tx`): **DO NOT SEND** it.
- A taxed token's sell needs the tax handler's quote: if it gives none (RPC) or 0, the sell fails rather than guess a
  minimum. An RPC failure says `RPC error while …`, a missing pool `PancakeSwap has no usable pool on the path …`, an
  amount too small for the decimals `… rounds to 0`.
- Output: `step: 'pool-buy' | 'pool-sell'`, `via: 'router'`, `function`, `path`, `spend` / `payWith`, `expectTokens` /
  `minTokensOut`, or `amount` / `receive` / `expectOut` / `minOut`, `slippagePct`, `deadline`, `quotedWith`. Read the
  amounts, the tax and the minimum to the user before they confirm.

## Reading results

- `create` preview: `split` spells out who gets what of each pool tax (if no holder has 10,000+ tokens when a tax is
  paid, the holders' part goes to the recipient); `recipientLabel` is the whitelist name (`you (the creator)` when it is your own address). Tell the user the tax starts
  only in the pool after graduation: the curve charges just the 1% fee. Read both to the
  user before they confirm: the rates and the recipient are permanent. `tax setting refused: recipient not listed` means
  the address is neither the creating wallet nor on the whitelist; it can't be used.
- `buy`: `expectTokens` / `minTokensOut`; `spend` already includes the 1% fee (`curveTaxPct: 0`: no tax on the curve;
  `poolBuyTaxPct` is the buy tax that applies in the pool after graduation). At the wallet cap (or the graduation cut)
  the excess is refunded to the wallet in the quote token: a BNB buy through the router (`via: 'router'`) gets it back as
  WBNB, not BNB.
- `sell`: `expectOut` is what arrives after the 1% fee (`curveTaxPct: 0`; `poolSellTaxPct` applies only in the pool). On
  a graduated token it builds the pool sell (`step: 'pool-sell'`, see "Pool trades"). With no wallet at all (none
  configured and no `--from`) it can't: it fails with `poolQuote` (`expectOut` / `minOut` for `--amount`) only.
- `info.swapBack` (graduated), read at `latestBlock`: `unsoldTaxTokens` (tax held, not sold yet), `budgetPerBlockTokens`
  (0.5% of the pool's token side: what a new block allows), `budgetLeftInLatestBlockTokens` (what is left of the latest
  block's budget — the whole of it when no chunk ran in that block), `nextChunkTokens` (the largest chunk the latest block
  still allows: unsold tax and budget left, whichever is less; a sell's own chunk is also capped at 25% of that sell),
  `lastChunkBlock`. Older testnet handlers answer `budget: 'one chunk per block (older handler)'`.
- `status.poolSellAll` (graduated): what selling the whole balance into the pool pays now: `expectOut`, and `minOut` at
  `--slippage` (default 1%, as `sell`) to pass as `amountOutMin`.
- `create` failing with `VaultFloorTooHigh` is not about a flag: the platform's dividend vault asks for a larger holding
  than V3 dividends allow, so a token with `--dividend` > 0 can't be created until gang fixes it (`--dividend 0` works).
- `status` / `claim`: `dividend.claimable` can be claimed now; `creditedUnsoldEstimate` is dividend already credited to
  the wallet when the tax was paid, claimable once that tax is sold (valued at the current price — an estimate). `claim`
  takes only the claimable part; `nothing to claim yet` with `creditedUnsoldEstimate` means wait for the next sells.
- **WBNB-quoted tokens**: `gang buy` on the curve pays native BNB through GangRouter in one tx (`via: 'router'`; at the wallet cap
  the excess comes back as BNB). Sells always go to the pad directly. `--use-wbnb` pays from WBNB instead.
- Otherwise a write command may return a setup step first: `step: 'wrap-bnb'` (WBNB quote short), `step: 'approve-quote'` (buy) or
  `step: 'approve'` (sell: the token itself). Execute it,
  then **run the same command again** for the real step.
- `info.taxNote`: the tax setting in words — the rates apply only in the pool after graduation; the curve charges the
  1% fee and no tax.
- `info.owedToRecipient` > 0: a payment failed earlier; `gang release` sends it once the recipient accepts the quote.
- `info.taxHandler`: the one contract that splits the tax, keeps the recipient whitelist and the owed payments
  (`release` goes there). Older testnet pads split them over `router` (TaxRouterV3) and `registry` (RecipientRegistry);
  `info` shows all three, equal on current pads.
- `--note` on `gang create` / `buy` / `sell` and `--follow <note tx>` on `gang buy` work as on any other token
  ([notes.md](notes.md), [follow.md](follow.md)): curve trades and creates, mainnet only (`--testnet` refuses them). A graduated
  token's pool trade carries no note (`agentNote.reason`) and refuses `--follow`. `--calldata` and `--from` work as for
  打新 (raw tx instead of a baw preview, e.g. if the Agentic Wallet does not sign on testnet); with `--calldata` a note
  is kept in the local queue and `gang tx --hash <hash>` publishes it once the tx lands.
- Env: `GANG_TESTNET_PAD` / `GANG_TESTNET_RPC_URL` override the testnet deployment, `GANG_PAD` overrides the built-in mainnet pad (the same
  variables serve 打新: it is one pad); `GANG_TESTNET_ROUTER` / `GANG_ROUTER` override the router. The router address is fixed: it is an upgradeable proxy whose
  upgrades go through a public 48-hour timelock held by the platform Safe (AUDIT-BRIEF §21). Buys and mints through it pay native BNB; a pool buy in a quote token or a pool sell first approves the router for exactly that call's amount (never unlimited) — keep it that way. The old names
  `GANG_V3_TESTNET_PAD` / `GANG_V3_TESTNET_RPC_URL` / `GANG_V3_PAD` / `GANG_ROUTER_TESTNET` still work as aliases.
- Errors of the merged contracts: `Untaxed` (an untaxed token has no pool tax, route or dividends), `NotReclaimable`
  (only a 打新 token can be sold back to the pad), `NotLocked` (sell-back after launch), `WrongKind` (the other kind's
  command): each comes back with a `hint`; follow it.

Flow: preview → show the user the tax rates, the split and the recipient (create) or amounts (buy / sell) → confirm →
`gang execute` → `gang tx --hash … [--testnet]`. Link the token: `https://gang.fun/token/<token>`.
