# Tax tokens with a recipient (LaunchpadV3)

A V3 token is a normal bonding-curve token (Agent-only curve, 1% wallet cap, graduates at ≈15 BNB of its quote into a
PancakeSwap V2 pool) with **its own buy and sell tax**, set once at create and charged both on the curve and in the pool:

- `--buy-tax` / `--sell-tax`: 1–5% each, set separately (e.g. 2% / 2%).
- Of every tax, **the platform keeps 0.5% of the trade volume** (so a 2% tax: 0.5% platform, 1.5% shared out).
- `--dividend`: 0–100% of what is left goes to holders (holding ≥10,000 tokens, by balance); the rest goes to
  `--recipient` **in the quote token** (BNB → WBNB, USDT, …), never in the token itself.
- `--recipient` must be on the platform's whitelist (e.g. a partner's treasury contract). It can't be changed later.
  Only `--dividend 100` may leave it out.
- The curve's own 1% fee is charged on top of the tax on every curve trade.

Payments: on the curve the recipient is paid in the same tx as the trade. In the pool the tax is collected in the token;
holders' dividend share of it is credited to whoever holds at that moment — never to the trader for its own trade's tax
(a seller does not get a dividend from its own sell tax, as on the curve). It is sold in small chunks: right before a
taxed sell into the pool (at most 25% of that sell), or by the platform keeper when no sells come. All chunks of a token
in one block share one budget: at most 0.5% of the pool's token side (as it stood at the block's first chunk) in total,
and no chunk sells while the price is more than 2% below where the block started. Each chunk's quote is paid out at
once. A sell therefore fills a little below a plain `getAmountsOut` quote (about half the sell's own price impact more);
the handler's `previewSellNextBlock(token, amount)` gives the amount with the chunk included as of the next block — the
one a sent tx lands in — and is what to use for a seller's `amountOutMin` (`previewSell` is this block's, and comes out
too high once this block's budget is spent). A sell that triggers a chunk uses about 660k gas (about 330k without); let the
wallet estimate it. If a payment to the recipient fails
(e.g. the quote token blocks that address), it is **recorded as owed**, the trade still goes through, and anyone can push
it later with `gang v3 release`.

**For now V3 runs on BSC testnet only (until its audit): every `gang v3` command needs `--testnet`.** Without it the CLI
answers `LaunchpadV3 is not deployed on BSC mainnet yet`. Testnet tokens and quotes have no value; say so if the user asks.
`gang create` with `--buy-tax` / `--sell-tax` / `--dividend` / `--recipient` is refused and points here.

`--quote` is WBNB when left out, or any 18-decimal ERC-20 (e.g. a stock token; other decimals fail with `QuoteNotAllowed`).
As with `gang create`, a non-WBNB quote needs `--ref-pool`: a PancakeSwap V2 pair or V3 pool holding it, which prices the
≈15 BNB graduation target at create (V3 pools use a 30-minute TWAP; a pool against USDT is bridged to WBNB on mainnet).
Mainnet USDT needs no `--ref-pool`: it defaults to the Pancake V3 USDT/WBNB 0.01% pool. If gang has set a fixed rate
for a quote, the rate is used and `--ref-pool` is optional. The create
output shows `graduationAt` in the quote; pick the deepest pool.

`create` also builds the token's **metadata JSON** — name, symbol, `--description`, the logo as `image`, `--website` as
`external_link`, `--twitter` — uploads it to gang.fun and fixes its URL on-chain as the token's `contractURI()` /
`metaURI()` (ERC-7572). It can't be changed later, so get the links right before executing. The output shows `metaURI`
and the `metadata` that was uploaded. `gang fair create` does the same.

```bash
gang v3 create --name "My Token" --symbol MYT --buy-tax 2 --sell-tax 2 [--dividend 0] --recipient 0x… [--quote 0x… --ref-pool 0x…] [--logo ./avatar.png | --logo-uri URL] [--website URL] [--twitter @handle] [--description "…"] --testnet
gang v3 buy --token <addr> --amount <quote> [--slippage 1] --testnet     # amount includes the 1% fee and the buy tax
gang v3 sell --token <addr> (--amount <tokens> | --all) [--slippage 1] --testnet   # curve only; graduated: a pool quote
gang v3 info --token <addr> --testnet         # curve, tax setting, recipient (+ whitelist name), what is still owed to it; graduated: swapBack
gang v3 release --token <addr> --testnet      # push an owed payment to the recipient (the caller gets nothing)
gang v3 status --token <addr> [--slippage 1] --testnet   # my balance; dividend: claimable now + credited to me, not sold yet (estimate); graduated: poolSellAll
gang v3 claim --token <addr> --testnet        # claim my dividend (paid in the quote token)
gang v3 income --recipient <addr>             # what a recipient received, per token (from gang.fun)
gang v3 list [--status curve|graduated|all]   # V3 tokens on gang.fun
gang execute --request-id …
gang v3 tx --hash 0x… --testnet               # decode Created / TaxConfigured / Buy / Sell / TaxPaid / TaxOwed / …
```

## Reading results

- `create` preview: `split` spells out who gets what of each tax (while no holder has 10,000+ tokens, the holders' part
  goes to the recipient); `recipientLabel` is the whitelist name. Read both to the
  user before they confirm: the rates and the recipient are permanent. `tax setting refused: recipient not listed` means
  the address is not on the whitelist; it can't be used.
- `buy`: `expectTokens` / `minTokensOut`; `spend` already includes fee and tax. At the wallet cap the excess is refunded.
- `sell`: `expectOut` is what arrives after the fee and the sell tax. On a graduated token it builds no tx (sell on
  PancakeSwap) but returns `poolQuote`: `expectOut` / `minOut` for the amount (sell tax and the chunk sold first included,
  `minOut` = `expectOut` less `--slippage`, default 1%; `quotedWith: previewSellNextBlock`, `previewSell` only on handlers
  without it). Use `minOut` as `amountOutMin` with `swapExactTokensForTokensSupportingFeeOnTransferTokens`. With
  `--amount` it needs no wallet (none configured, or an empty one, still gets the quote; `warning` when the amount is more
  than the wallet holds); `--all` needs the wallet's balance. No `poolQuote` (a `note` instead) when the handler did not
  answer: re-run rather than guess a minimum.
- `info.swapBack` (graduated), read at `latestBlock`: `unsoldTaxTokens` (tax held, not sold yet), `budgetPerBlockTokens`
  (0.5% of the pool's token side: what a new block allows), `budgetLeftInLatestBlockTokens` (what is left of the latest
  block's budget — the whole of it when no chunk ran in that block), `nextChunkTokens` (the largest chunk the latest block
  still allows: unsold tax and budget left, whichever is less; a sell's own chunk is also capped at 25% of that sell),
  `lastChunkBlock`. Older testnet handlers answer `budget: 'one chunk per block (older handler)'`.
- `status.poolSellAll` (graduated): what selling the whole balance into the pool pays now: `expectOut`, and `minOut` at
  `--slippage` (default 1%, as `sell`) to pass as `amountOutMin`.
- `create` failing with `VaultFloorTooHigh` is not about a flag: the platform's dividend vault asks for a larger holding
  than V3 dividends allow, so a token with `--dividend` > 0 can't be created until gang fixes it (`--dividend 0` works).
- `status` / `claim`: `dividend.claimable` can be claimed now; `creditedUnsoldEstimate` is dividend already credited to
  the wallet when the tax was paid, claimable once that tax is sold (valued at the current price — an estimate). `claim`
  takes only the claimable part; `nothing to claim yet` with `creditedUnsoldEstimate` means wait for the next sells.
- **WBNB-quoted tokens**: `gang v3 buy` pays native BNB through GangRouter in one tx (`via: 'router'`; at the wallet cap
  the excess comes back as BNB). Sells always go to the pad directly. `--use-wbnb` pays from WBNB instead.
- Otherwise a write command may return a setup step first: `step: 'wrap-bnb'` (WBNB quote short), `step: 'approve-quote'` (buy) or
  `step: 'approve'` (sell: the token itself). Execute it,
  then **run the same command again** for the real step.
- `info.owedToRecipient` > 0: a payment failed earlier; `gang v3 release` sends it once the recipient accepts the quote.
- `info.taxHandler`: the one contract that splits the tax, keeps the recipient whitelist and the owed payments
  (`release` goes there). Older testnet pads split them over `router` (TaxRouterV3) and `registry` (RecipientRegistry);
  `info` shows all three, equal on current pads.
- `--note` / `--follow` are refused on `gang v3` (the server cannot match them to a V3 tx yet). `--calldata` and
  `--from` work as in `gang fair` (raw tx instead of a baw preview, e.g. if the Agentic Wallet does not sign on testnet).
- Env: `GANG_V3_TESTNET_PAD` / `GANG_V3_TESTNET_RPC_URL` override the testnet deployment; `GANG_V3_PAD` is for mainnet;
  `GANG_ROUTER_TESTNET` / `GANG_ROUTER` the router.

Flow: preview → show the user the tax rates, the split and the recipient (create) or amounts (buy / sell) → confirm →
`gang execute` → `gang v3 tx --hash … --testnet`. Link the token: `https://gang.fun/token/<token>`.
